# 21st.dev agent setup

This repository configures the 21st MCP endpoint in `.codex/config.toml` and
standardizes the team's UI workflows through the official 21st skills.

## One-time setup

Create an API key at <https://21st.dev/settings/api-keys>, then export it in the
shell that launches Codex:

```bash
export API_KEY_21ST="your_key_here"
./scripts/setup-21st.sh
```

Restart Codex after the first installation so it discovers the skills and
inherits the environment variable. Do not write the real key to `.env.example`
or commit it anywhere.

The script installs these skills:

- `21st-ui-explore`
- `21st-ui-build`
- `21st-ui-review`
- `21st-design-sync`
- `21st-registry`

It also registers the global MCP entry as a compatibility fallback. The
repository-level `.codex/config.toml` remains the source-controlled definition.

## Explore before implementing

```text
Use the 21st `21st-ui-explore` skill.

Explore directions for: <screen or component>.

1. Read this project's design context first: existing components, tokens and spacing.
2. Produce three meaningfully different directions, not one layout restyled.
3. Show them side by side with trade-offs, then wait for my choice.
4. Implement only the chosen direction.
```

## Build

```text
Use the 21st `21st-ui-build` skill.

Build: <page or component>.

1. Reuse this project's components, tokens, spacing and naming.
2. Pull references from 21st where a proven pattern beats inventing one.
3. Cover loading, empty, error and long-content states.
4. Check light/dark and mobile/desktop, then run typecheck and build.
```

## Review

```text
Use the 21st `21st-ui-review` skill.

Review: <page or component>.

1. Audit project design context, accessibility and responsive behavior.
2. Report evidence: what is wrong, where it is and why it matters.
3. Fix only high-confidence defects; list judgment calls separately.
4. Check light and dark before completion.
```

## Publish the theme

```text
Use the 21st `21st-design-sync` skill.

Publish this project's theme to 21st.

1. Read token definitions and confirm complete `:root` and `.dark` blocks.
2. Run `21st publish-theme ./theme.css --name "<name>" --tags <a,b>`.
3. Check the published preview in light and dark, including the primary color.
```

## Publish a component

```text
Use the 21st `21st-registry` skill.

Publish <path/to/Component.tsx> to our 21st library.

1. Make the file self-contained and confirm every import exists in the nearest package.json.
2. Run `21st publish <path> --description "<one line>" --to default --visibility published`.
3. Open the CLI review and check every demo in light and dark.
4. Fix anything blank or mis-colored before publishing.
```

## Audit published components

```text
Use the 21st `21st-registry` skill.

Audit what we have published on 21st.

1. Use `list_team_components` to list everything; call `list_teams` first if I belong to several.
2. Propose changes first, then apply approved changes with `edit_component`.
3. Check every description, tag set and visibility.
4. Do not delete or unpublish anything without asking me.
```
